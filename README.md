# dsh-character-long-memory（长期有效记忆伙伴）

一个以「人」为单位的长期记忆插件。给 AI 一个记事本，让它记住你说的那些人，以及他们在你生活里的位置。

不是给论文用的，是给每天真的在跟 AI 说话的人用的。

> **前置条件**：必须装在 `digital-life-core` 里。它不是一个独立的 DSH 插件，离开那个宿主跑不起来。

## 三十秒装好

1. 找到器官目录：

```
<dsh-desktop>/harness/profiles/.generations/live/digital-life-core+<版本>/node_modules/digital-life-core/web-ui/organs/self-made/
```

2. 把 `listener.ts` 丢进去

3. 重启 DSH

日志里出现这一行，就是接上了：

```
[life-os] 记忆路由已接她的海马体：listener（想起→organ_listener_recall，记下→organ_listener_remember）
```

## 它解决什么

普通 AI 聊完就忘。加了向量库的 AI 记得住，但记成一片没有结构的意思——你去问「老张最近怎么样」，它翻出来的是二十条碎片。

这个插件换了个维度：**以人为单元存**。

- 你说到谁，事就挂在谁名下
- 总目录只记一行「某天 谁 提了什么事」，随时能扫
- 越近的事越重，越远的事越淡，被重新提起会回温
- 承诺、冲突、关系定性打上标记，永不压缩
- 认不出是谁，它不编，先记一笔待问，之后自然地问你一句

## 记忆怎么衰减

权重只决定一件事：这条记忆现在有多容易被想起来。它不决定存不存，也不决定删不删。

```
两条曲线叠加：
快分量 = 1.1  × exp(-天数 / 45)  × (0.6 + 1.2 × 情绪) × 召回加成
慢分量 = 0.45 × exp(-天数 / 730) × (0.8 + 0.4 × 情绪)
权重   = min(3.6, 快 + 慢)，下限 0.05

召回加成 = 每次被翻出来 +0.2，这 0.2 自己按 7 天半衰
```

为什么是两条：细节忘得快，而「老王住过院」这件事本身几年都不会消失。单条衰减曲线做不到——要么忘得太快，要么什么都忘不掉。

一条情绪强度 0.6 的记录实测：8 天前约 1.7，8 个月前约 0.35，一年前约 0.28，五年后落到下限。

## 压缩不等于删除

第一版把「权重低」和「内容变短」绑在一起，权重一低就把原话压掉。这是把省存储和省注意力搞混了，是设计错误。

现在的做法：

- **存储永不压缩。** 原话永远在，一个字不删。
- **压缩只发生在展示层。** 一条记忆被翻出来时给你多少细节，由它此刻的权重决定：

| 权重 | 你看到的 |
| --- | --- |
| ≥ 1.2，或带 keep 标记 | 原话，一个字不少 |
| 0.5 — 1.2 | 一句话摘要，约 36 字 |
| < 0.5 | 只剩一个影子，约 18 字 |

同一件事，今天提起来是完整的，三年后只剩一个影子；但你追问「当时他怎么说的」，原话还在。

**记住的是细节会淡，记忆本身不会消失。**

## 夜间整理

每 6 小时自动跑一次，也可以手动 `tidy`。做三件事：

**一是合并重复。** 同一件事你说了两遍，只留一条。判据是两条一起看：

```
Jaccard（二元组交集 / 并集）          ≥ 0.75  合并
包含度（二元组交集 / 较短者的长度）   ≥ 0.82  合并
```

只用 Jaccard 会把「心脏的问题」和「心脏的毛病」判成两件事——长度一长，分母就被拖大。包含度补的就是这个：一句话基本被另一句盖住时，它就是同一条。

合并时保留更早的日期、更长的原话，保护标记取并集，召回次数累加。

**二是连线不合并。** 像是同一件事的两种说法、但不该压成一条的（相似度够、时间在十天内），就在两条之间牵一根线。想起一个，另一个在旁边。这种关系留着比合并有用——人本来就会从一件事想到另一件。

**三是清悬空。** 人档案里指向已被删事件的 id、总目录里重复的行、合并后残留的连线，全部清掉。

不清理的后果不是变慢，是变脏：一年后库里一半是同一件事的不同说法，检索出来的每一条都对，但拼起来是废话。

## 检索

两条路进同一个库。

**按人**：名字或别名命中，把他名下的事按权重排开。

**按话**：中文没有空格，用二元组做倒排索引，再挂一张同义表——搜「手术」能翻出「住院」那条，搜「走了」能翻到「去世」。

```
hit   = 命中的二元组数（查询串先做同义扩展）
score = hit × 2 + 权重 + 保护标记加成
```

命中准度排在权重前面。找错人的细节，比找不到更糟。

`recall` 有 `detail` 开关：`auto`（默认，按权重决定详略）、`raw`（一律原话）、`gist`（只给摘要）。

## 时序图

记忆不只是点，还有边。但边不是标签——标签永远为真，事实会变。

每条边记两条时间轴：

```
validFrom / validTo        这件事在世界上成立的区间
recordedAt / invalidatedAt 我们什么时候知道的、什么时候发现它不作数了
```

差别在例子裏：老张 2020 年到 2024 年在阿里上班，你 2024 年才知道，2025 年听说他跳槽了。「他在阿里」这条不是假的，它只是到此为止了。所以不作废删除，只标 end。

**自动连三种边：**

| 边 | 什么时候连 |
| --- | --- |
| `similar` | 同一个人、十天内、文字高度重合——同一次的两个说法 |
| `follows` | 同一个人、一百二十天内、文字中等重合——后来的那件事 |
| `next` | 同一个人相邻的两件事，时间差一年以内——接着发生 |

`next` 这条不看文字。文字可以完全不像，「住院」和「辞职」在字面上没关系，但时间上是连着的，人的记忆本来也是这么串的。

**手动连一种：`supersede`。** 由模型判断，不由规则判断。因为「这件事作废了」需要理解，规则判不出来。调 `fix` 的 `supersede`：旧事保留，标一个结束时间，新事指回去。

**怎么用：**

`graph` 从一个人或一件事往外走，默认一跳，最多两跳。人和事的归属关系不存成边（会重复），遍历时现算。

`recall` 会自动带出相邻的那件事，标一个 `↳`。预算不够才不带。

实测一个三件事的小场景：老张住院、小李去探望、老张决定辞职。从老张出发两跳，能走到小李；「住院」和「辞职」被时间串在一起。

## 主题：不挂在人身上的事

这套东西最初只认人。问题是，人不可能只在聊天里谈人——大部分时候你在谈事。

所以主题是独立节点，和人是平级的：

- `remember` 带 `topic` 就建一个主题节点，事件挂上去，中间连一条 `about` 边
- 一条记忆可以同时挂在人身上和主题上
- 没有任何人参与的事，直接挂在主题下，不再追问「这是谁的事」

这一条让插件在纯工作场景里也能用。「决定用器官的方式做插件，不改 L0」这种话，以前没地方放。

## 日志层：主人在做什么

任务场景里没有人物可挂。这一层记的是「某人哪天在做什么」。

主人自己也是一个节点，名字叫「我」。`diary` 一句话就能写一条：日期、在做什么、归到哪个主题。不用判断涉及谁，也不会追问这是谁的事。

因为「我」和别人一样是普通节点，日志白拿了整套能力：

- 一样吃时间衰减，去年干的事会淡
- 一样能检索：`journal` 按天翻，`recall` 也能按人翻
- 一样挂在图上：从某个主题出发能走到「我」做过的那些事
- 一样能合并重复，同一件事说两遍不会变成两条

提示词里会多一行「你在做」，所以聊着聊着它能主动提一句「这块上周不是改过一次吗」。

「我」不会出现在人物列表里——那是给人看的，不该混进一个「我」。

## 因果

`fix` 的 `cause` 动作。

不做自动推断。因果需要理解，规则判不出来，自动推出来的因果比没有更糟。和 `supersede` 一样，是模型判断、手动标的。

## 什么时候它闭嘴

空库，或者一个月没记过任何东西——完全不注入。

理由很直接：一个只用来布置任务的人，每轮被塞一句「记得记人和事」是纯噪音。宁可安静。

代价是：库空的时候，模型只是从工具表里知道有这么个东西，不会主动想起来用它。这是有意的取舍。

## 不确定的时候它怎么办

这是整套设计里最像人的部分。

**先存后问，不打断。** 认不出是谁、关系说不清、时间对不上，先记成一条待办，继续聊。下次注入提示时会带一句「挂着 N 个疑问」，合适的时机才问一句，一次只问一个。

**问过就销账。** `fix` 和 `settle` 都会关掉对应的问题，不会反复问。

**宁可说记不清。** 提示词里明写：聊到已知的人，先翻档案再开口，别凭空猜。编一次，整个库就不再可信。

## 情绪

`tone` 返回的不是答案，是姿态：

- `先接住，别讲道理`（0.95）
- `沉下来，陪着`（0.85）
- `收着点，多听少说`（0.6）
- `平稳地听`（0.35）
- `替他高兴`（0.65）
- `一起高兴`（0.85）

强度够高时可以让它真的影响 AI 自己的内分泌（`apply: true`），听你讲难事它会沉一点。判断情绪和真的被影响是两回事，只做前者听起来像演戏。

判断是词典打分的，不调模型。快、免费、可解释，缺点是看不懂反讽，也读不出「他嘴上说没事」这种话里的反话。这是已知短板。

## 已知局限（请先读这段）

**1. 捕获靠提示词强约束，不是真的钩子。**
器官 ABI 里没有「看用户消息」的入口，所以「每件事都记得住」依赖于模型遵守注入的规矩。做不到百分之百，模型偶尔会忘。这是当前架构的天花板，不是懒。

**2. 认人靠模型。**
同名的两个人、称呼漂移（张总 / 老张 / 张老师）、一句话里三个人，都会出错。`fix` 是止血带，不是疫苗。

**3. 没有界面。**
只有 `export` 能吐 Markdown。真正的可视化要等宿主开放 web 路由给器官。

**4. 单用户。**
所有记忆假定只有一个「你」。多人共用一份数据会串味。

**5. 隐私。**
库里存的是**关于第三方**的信息，而且他们没有同意过。自己用没问题；公开分发时，这件事必须在 README 里说清楚。`forget` 支持按人彻底删除。

**6. 检索是词面的，不是语义的。**
二元组 + 同义表能救回一半，但救不了「他觉得那事儿挺费劲」和「他压力很大」之间那种距离。器官沙盒里没有 embedding 通道，真上向量得等宿主开放。同义表也是手工维护的，冷门领域会漏。

## 一处不能踩的坑

原生工具注册要求 `parameters` 是一个**属性表**，不是 JSON Schema：

```js
// 对
parameters: {
  text: { type: 'string', description: '...', required: true },
}

// 错：会报 parameters.type must be a value schema object
parameters: {
  type: 'object',
  properties: { text: { type: 'string' } },
}
```

允许的类型只有 `string | number | integer | boolean | null | object | array | json`，注解只有 `description | title | default | examples`，必填写 `required: true`。处理函数叫 `execute`，不叫 `handler`。持久化用 `ctx.kv`，但必须声明 `fs:organ` 能力，否则每次读写都会被拒绝，而且不报错——只会静默地什么都存不下。

这是我踩了一整轮才知道的。

## 接进数字生命：一个字段的事

digital-life-core 的记忆器官不是存储，是个插座。

它的 `routes` 里指着两个工具名——一个「想起」、一个「记下」。核心会扫 `self-made` 目录，找 `kind === 'memory'` 的自写器官，找到就把路由接上去，运行时也能换。源码注释写的是「路由是她此刻在用谁的海马体」。

所以接进去只要一个字段：

```js
manifest: { name: 'listener', kind: 'memory', ... }
```

日志会打：

```
[life-os] 记忆路由已接她的海马体：listener（想起→organ_listener_recall，记下→organ_listener_remember）
```

接上之后白拿四样东西：

| 拿到的 | 说明 |
| --- | --- |
| 锚点 | 写下一条记忆时，自动记下当时的情绪快照，想起时能带回来 |
| 注意力倾斜 | 情绪高的时候优先想起危险的事，平静时优先日常 |
| 命中反馈 | 想起来了给她一点愉快，想不起来给她一点难受 |
| 缺口 | 连续想不起来，自动变成一条执念 |

代价是每次调用要花她的能量，结果还会被它的预算和格式再加工一遍。

为此 `recall` 会额外返回一段 `structured: { total, shown: [{ id, text }] }`——那是它要读的清单，`total` 决定"这次算命中几条"。

### 接上之后要注意的

**命名抢占。** 核心按名字排序取第一个 `kind === 'memory'` 的自写器官。以后装了第二个记忆器官，谁排在前面谁接管，没有优先级字段可用。改名要慎重。

**不会叠加两次排序。** 只要我们返回 `structured.shown`，它就把我们当成"已经排过序的层"，只做外部审计，不再二次倾斜。源码里专门写过：两套各乘三就是九倍，那是失真不是重视。

**预算压在 3000。** 它的上限是 4000，超了会重写压缩。我们把返回上限压在 3000，永远碰不到那条线。实测它的 `rewrites` 一直是 0，说明一次都没被剪过。

**锚点靠文本回填。** 存的时候它记下当时的情绪快照，想起时按文本比对。所以 `shown` 里放的是**原话**，不是按权重截短的展示稿——放展示稿会匹配不上，锚点就白记了。

**每次调用都扣她的能量。** 这是它的设计：感知是有成本的。不是 bug，但要知情。

**它带的 `topK` 要照办。** 回读校验时它会带 `topK: 5` 来问，不理它就会白拉一大段。

## patches/：给核心打运行时补丁

`patches/dashboard-fix.ts` 不是记忆插件的一部分，是一个补丁器官。

它处理 `digital_life_dashboard` 的报错：核心把它的 output schema 写死成 `additionalProperties: false`，但返回值里多带了 `restMode` 和 `naturalCap` 两个没声明的字段，校验器于是把整条结果拒掉，工具直接不可用。

```
Error: tool "digital_life_dashboard" returned invalid output:
"value.restMode" is not a declared property (additionalProperties: false);
"value.naturalCap" is not a declared property (additionalProperties: false)
```

**它修不了这个 bug，只能把报错换成一句人话。**

原因：核心工具的 after 补丁挂在 `tools/post-execute`，那时校验已经做完了；而且那条链只允许替换 content 文本，不允许替换 value。只有器官工具才有 `execute` 外层可改。根因在 L0，器官层碰不到。

用法跟 `listener.ts` 一样：丢进 `self-made/`，重启。零工具、零注入，留着不碍事。上游修好之后删掉即可。

## 出处

为「AI 的长期记忆以人物为基本单元存放」这个想法做的实现。最初的设计只有三件事：人物档案、时间衰减、主动追问。后来补上了纠错、导出、情绪判断和遗忘权。
